================================================================================
0. PURPOSE
================================================================================

Implement a complete reduced-parameter experimentation framework for the paper
"Dependency-Aware Failure Bounds for QC-MDPC Bit-Flipping Decoders".

The implementation must demonstrate, on finite reduced QC-MDPC domains, that the
proposed dependency-aware profile framework:

  1. produces valid non-vacuous upper bounds on key-conditioned failure
     probabilities p_H;
  2. separates high-failure keys better than simpler diagnostics;
  3. yields sharper profile-tail and repeated-use static-key diagnostics than
     average-only or simpler profile models;
  4. is fully reproducible from deterministic Docker commands and recorded
     configuration files.

This implementation is not intended to prove production-parameter BIKE DFR. The
artifact is a reduced-parameter certification and diagnostic framework.

================================================================================
1. CLAIMS THE IMPLEMENTATION MUST SUPPORT
================================================================================

The implementation must support the following experimentally checkable claims.

Claim A: Exact finite-domain certification.
For selected toy parameter sets, the implementation enumerates all keys and all
constant-weight errors, computes exact p_H for every key, and computes exact key
profile masses. This gives an exact reduced-domain distribution of p_H.

Claim B: Non-vacuous profile-class bounds.
For the same exact domains, the implementation constructs profile-class upper
bounds p_phi^+ and verifies that p_H <= p_{kappa(H)}^+ for every certified key.
The bounds are non-vacuous when most p_phi^+ are strictly less than 1 and when
reported looseness is finite and meaningfully below the trivial bound.

Claim C: Dependency-aware separation.
The full profile model M3 must be compared against simpler diagnostics M0, M1,
and M2. The comparison must measure coverage, looseness, tail-curve quality,
rank correlation with exact p_H, and recall of high-p_H keys.

Claim D: Finite-state upper-process instantiation.
For each profile bin, iteration, and compressed residual state, the implementation
constructs miss/false count envelopes Q_i^+(phi,x;m,l) from enumerated decoder
trajectories and propagates a non-normalized upper process to obtain a certified
finite-state upper bound p_{phi,FS}^+.

Claim E: Diagnostic larger reduced instances.
For r=31,d=5,t=4 and selected additional parameter sets, the implementation
samples or stratifies keys, enumerates or samples errors as configured, and
reports diagnostic generalization results. These larger runs must be clearly
labeled as sampled-set certificates or diagnostics, not full-keyspace proofs.

Rust. Python scripts are allowed only for plotting and final report generation.

5. MATHEMATICAL OBJECTS TO IMPLEMENT
================================================================================

5.1 Key space

A two-block QC-MDPC key is H=(h0,h1), where h0 and h1 are d-subsets of Z_r.
The implementation represents h0 and h1 as sorted Vec<u16>.

For experiments, use the default reduced keyspace:
  - h0 and h1 are independent d-subsets of {0,...,r-1};
  - no production BIKE key filter is applied unless explicitly configured;
  - r is odd in all supplied configs;
  - keys are identified by key_id and by canonical support strings.

5.2 Positions and columns

The set of bit positions is J = {0,1} x Z_r. Encode position j=(a,z) as:

  j = a*r + z,  where a in {0,1}, z in {0,...,r-1}.

The column neighborhood Gamma_H(a,z) is:

  Gamma_H(a,z) = Supp(h_a) + z mod r.

The syndrome space has r check positions. The implementation uses a fixed-size
bitset for syndrome support.

5.3 Error space

For a configured error weight t, enumerate or sample errors e as t-subsets of
{0,...,2r-1}. The default theorem-grade experiments enumerate all t-subsets.

5.4 Syndrome computation

For an error support E, compute syndrome support as XOR of the column masks:

  s_H(E) = XOR_{j in E} column_mask[j].

5.5 Deterministic threshold bit-flipping decoder

The decoder is configured by:
  - iteration bound I;
  - threshold schedule T[0..I-1];
  - flip policy: flip all positions j whose counter sigma_j >= T_i;
  - success condition: reconstructed error estimate equals original error;
  - zero syndrome but wrong reconstruction counts as wrongzero failure.

At iteration i:
  - residual error mask E_i = e_mask XOR estimate_mask;
  - residual syndrome s_i = syndrome(E_i);
  - for every bit j, counter sigma_j = popcount(column_mask[j] & s_i);
  - flip set F_i = {j : sigma_j >= T_i};
  - estimate_mask ^= F_i;
  - E_{i+1} = E_i XOR F_i;
  - if E_{i+1}=0, classify success;
  - if syndrome(E_{i+1})=0 and E_{i+1} != 0, classify wrongzero;
  - after I iterations, if not success, classify timeout unless a configured
    deterministic nonzero halt rule applies.

The implementation must log enough trajectory data to reconstruct state counts
and transition envelopes.

================================================================================
6. BITSET REPRESENTATION
================================================================================

Implement a compact deterministic bitset abstraction.

6.1 Syndrome bitset

For r <= 128, syndrome masks can be represented as u128.

Required methods:
  - empty() -> SyndromeMask
  - set(pos)
  - xor_assign(other)
  - and(other) -> SyndromeMask
  - popcount() -> u32
  - is_zero() -> bool
  - to_hex() -> String

Use u128::count_ones for popcount.

6.2 Error / bit-position mask

For 2r <= 256, use a custom Mask256 as [u64;4]. This covers r up to 128.

Required methods:
  - empty()
  - set(pos)
  - clear(pos)
  - contains(pos)
  - xor_assign(other)
  - union/intersection if needed
  - popcount()
  - is_zero()
  - iter_ones(max_bits) -> iterator over set positions
  - to_hex()

Use four u64 limbs. All operations must mask off unused high bits when needed.

6.3 Column masks

Store column masks as Vec<SyndromeMask> of length 2r.

7.3 src/profile.rs

Responsibilities:
  - compute structural profile coordinates for each key;
  - serialize profile data;
  - compute profile coordinates used in M1, M2, M3.

Profile coordinates to implement in v01:

  A. cyclic-overlap spectra D_ab(Delta)
     For a,b in {0,1}, Delta in Z_r:
       D_ab(Delta) = |Supp(h_a) intersect (Supp(h_b)+Delta)|.

  B. local cycle pressure
       C4_loc = sum over nontrivial (a,b,Delta) of binom(D_ab(Delta),2).

  C. maximum nontrivial overlap
       D_max = max nontrivial D_ab(Delta).

  D. overlap histogram Lambda
       Lambda[k] = # nontrivial indices with D_ab(Delta)=k.

  E. canonical near-codeword family N0
       N0 = rotations of (h0,0) and rotations of (0,h1).

  F. near-codeword overlap tail A_N(u)
       For configured u_values, compute union-bound upper tail:
         A_N(u) <= sum_{N in N0} Pr[|E intersect N| >= u]
       under uniform t-subset errors over 2r positions.
       Cap at 1.0.

  G. low-syndrome gathering counts G_H(m,l)
       For configured m <= MG and l <= LG, enumerate all m-subsets of J and
       count how many have syndrome weight <= l.
       Default MG must be small, e.g. MG=3 or 4.

  H. fixed-point indicator count B_H(M,Tset)
       For all nonempty residual supports E with |E| <= MB, compute syndrome.
       If syndrome nonzero and there exists T in configured Tset such that no
       position has counter >= T, count E as fixed-point candidate.
       Default MB must be small, e.g. MB=3 or 4.

  I. local weighted-overlap budget summary Omega proxy
       For each candidate residual support encountered during decoding, the
       state module computes Omega(E). At key-profile level, store optional
       summary values for singletons/pairs:
         Omega_pair_max = max_{j,k} I_H(j,k)*1[I_H(j,k)>=2].

Profile output columns in profiles.csv:

  run_id,key_id,r,d,t,c4_loc,d_max,lambda_json,
  an_u_json,gather_json,b_fixed,tset_json,omega_pair_max,profile_hash

Profile hash:
  - deterministic SHA-256 over serialized profile coordinates used for M3 bins.

7.5 src/state.rs

Responsibilities:
  - compute compressed residual state chi_H(E);
  - compute state bins for M1, M2, and M3;
  - assign deterministic state_id values.

State models:

  M1: syndrome-weight model
      x = (t_residual, syndrome_weight)

  M2: near-codeword model
      x = (t_residual, syndrome_weight, u_near_bin)

  M3: full dependency-aware model
      x = (t_residual, syndrome_weight, u_near_bin, fixed_bin, omega_bin)

Terminal states:
  - succ
  - bad

State computation:
  - if residual mask E is zero: succ;
  - if syndrome(E)==0 and E != 0: bad/wrongzero;
  - if fixed-point predicate is true under current or any configured threshold:
    fixed_bin marks it; if configured strict_absorbing=true, map to bad;
  - otherwise compute tuple.

Near-codeword overlap U_N(E):
  - N0 consists of all rotations of h0 in block 0 and h1 in block 1.
  - U_N(E) = max overlap with any N in N0.

Omega(E):
  - For each candidate bit j, compute
      W_H(j,E)=sum_{k in E, k!=j} I_H(j,k)*1[I_H(j,k)>=2].
  - Omega(E)=max_j W_H(j,E).
  - Bin Omega using configured omega_bins.

State serialization:
  state_id = stable hash of model_name + tuple + terminal marker.

7.6 src/enumerate.rs

Responsibilities:
  - enumerate errors;
  - run key/error loops;
  - collect p_H and trajectory counts;
  - support checkpointing/resume if configured.

Exact p_H computation:

  failures = 0
  total = binom(2r,t)
  for e in combinations(2r,t):
      result = decode_with_logs(...)
      if outcome != Success: failures += 1
      update state_counts and transition counts
  p_H = failures / total

Transition data to collect:

For each model M in {M1,M2,M3}, each key H, iteration i, and state x:
  - denominator count: # trajectories reaching x at iteration i;
  - count by pair (m,l): # trajectories in x with missed_count=m,false_count=l;
  - successor state count: # trajectories moving x -> y;
  - outcome counts.

Do not store per-error logs by default. Store aggregate counts. Per-error logs may be
enabled only for debug runs.

7.7 src/binning.rs

Responsibilities:
  - construct profile bins for M0, M1, M2, M3;
  - enforce equal or comparable bin budgets;
  - produce bins.csv.

Model definitions:

  M0: global average-only model.
      All keys are in one bin.

  M1: key-level bin uses simple structural/syndrome proxies only.
      v01 key bin coordinates:
        - d_max only, or c4_loc quantile only.
      For state process, M1 uses (t_residual,S).
      For key-tail direct binning, use quantile bins of c4_loc with bin_budget.

  M2: near-codeword-only key model.
      Key bin coordinates:
        - A_N(u*) quantile, where u* is configured, plus optional d_max if needed
          only to break ties.
      State process uses (t_residual,S,u_near_bin).

  M3: full profile model.
      Key bin coordinates:
        - c4_loc quantile;
        - d_max exact or binned;
        - A_N(u*) quantile;
        - selected G_H(m,l) quantile;
        - B_H fixed-point count binary/quantile;
        - omega_pair_max bin.
      State process uses (t_residual,S,u_near_bin,fixed_bin,omega_bin).

Equal bin budget rule:
  - For each configured bin_budget B, construct at most B nonempty bins per model.
  - Use deterministic quantile binning on training/certified keys.
  - For exact full-domain runs, bins are built on the whole domain because the
    claim is descriptive/certified for that finite domain.
  - For held-out diagnostics, bins must be learned on the training split only.

Required output bins.csv columns:
  run_id,model,bin_budget,bin_id,key_count,bin_descriptor_json

7.8 src/certify.rs

Responsibilities:
  - direct profile-bin bounds;
  - finite-state upper-process bounds;
  - tail lifting;
  - multi-query lifting.

7.8.1 Direct bin bounds

For each model and bin phi:

  p_phi_max = max_{H in certified bin} p_H.
  p_phi_mean = average_{H in bin} p_H.
  nu_phi = key_count_phi / total_certified_keys.

Write bin_bounds.csv:

  run_id,model,bin_budget,bin_id,key_count,nu_phi,p_phi_max,p_phi_mean,
  ph_min,ph_median,ph_p95,ph_max

7.8.2 Transition envelope Q_i^+

For each model M, bin phi, iteration i, state x, and pair (m,l):

  For every key H in phi:
      q_{i,H}(x;m,l) = count_{H,i,x,m,l} / denom_{H,i,x}
      if denom=0, skip H for that state.

  Q_i^+(phi,x;m,l) = max over H with denom>0 of q_{i,H}(x;m,l).

Store transition_envelopes.jsonl with records:

  {
    "run_id": "...",
    "model": "M3",
    "bin_budget": 64,
    "bin_id": 12,
    "iteration": 2,
    "state_id": 981273,
    "state_tuple": {...},
    "denom_key_count": 37,
    "pairs": [ {"m":0,"l":0,"q_plus":0.91}, ... ],
    "row_sum_q_plus": 1.17
  }

Rows are allowed to sum above 1.

7.8.3 Successor relation

For v01 enumeration-first certification, compute successor relation directly from
observed trajectories:

  observed_successors(phi,x,m,l) = set of y observed among certified trajectories
  in bin phi, state x, and count pair (m,l).

For theorem-grade exact full-domain runs, this observed relation is exact for the
full enumerated domain.

For sampled-key runs, it is exact only for the certified sampled-key set and must be
reported as such.

7.8.4 Upper kernel K_i^+

For each phi,x,y:

  K_i^+(phi;x,y) = sum over (m,l) such that y in observed_successors(phi,x,m,l)
                  of Q_i^+(phi,x;m,l).

Terminal states succ and bad are absorbing:

  K_i^+(succ;succ)=1, K_i^+(bad;bad)=1.

Rows may sum above 1.

7.8.5 Initial upper measure alpha_0^+

For each phi and state y:

  alpha_0^+(phi;y) = max over H in phi of Pr_{e in E_t}[chi_H(E_0)=y].

Compute this from exact state counts at iteration 0.

For sampled-error runs, use one-sided confidence upper bounds. In v01 exact toy and
r=31,t=4 selected runs should use exact enumeration where feasible.

7.8.6 Propagation

For each phi:

  alpha = alpha_0^+
  for i in 0..I-1:
      alpha_next[y] = sum_x alpha[x] * K_i^+(x,y)
      alpha = alpha_next

  p_phi_FS_plus = min(1, alpha[bad] + sum_{nonterminal y} alpha[y])

Write fs_bounds.csv:

  run_id,model,bin_budget,bin_id,p_phi_fs_plus,row_mass_max,
  alpha_total_final,bad_mass_final,nonterminal_mass_final,
  vacuous_flag

7.8.7 Tail lifting

For each model and bin budget:

  Exact empirical tail:
      tail_exact(tau) = # {H: p_H > tau} / #keys

  Direct-bin upper tail:
      tail_direct(tau) = sum_{phi: p_phi_max > tau} nu_phi

  Finite-state upper tail:
      tail_fs(tau) = sum_{phi: p_phi_FS_plus > tau} nu_phi

  Average bound:
      delta_direct = sum_phi nu_phi * p_phi_max
      delta_fs = sum_phi nu_phi * p_phi_FS_plus

  Static-key q-query:
      failq_direct = sum_phi nu_phi * (1 - (1-p_phi_max)^q)
      failq_fs = sum_phi nu_phi * (1 - (1-p_phi_FS_plus)^q)
      failq_exact = average_H (1 - (1-p_H)^q)
      failq_avg_union = min(1, q * average_H p_H)

Write tail_curves.csv and metrics.csv.

7.9 src/metrics.rs

Responsibilities:
  - coverage;
  - looseness;
  - additive gap for p_H=0;
  - Spearman rank correlation;
  - top-tail precision/recall;
  - AUC if implemented;
  - tail-curve error;
  - ablation metrics.

Metrics:

  coverage = fraction of H such that p_H <= p_{kappa(H)}^+ + epsilon.
  epsilon = 1e-15 for floating errors.

  looseness_ratio for p_H>0:
      p_bound / p_H

  additive_gap_zero for p_H=0:
      p_bound

  median_looseness, p95_looseness, max_looseness.

  vacuous_bin_fraction:
      # bins with p_bound >= 1 / # nonempty bins

  Spearman:
      rank correlation between key score and p_H.
      Use p_bound assigned to key as score.

  Top-tail recall:
      For top alpha fraction of keys by exact p_H, alpha in {0.01,0.05,0.10}:
        recall@alpha = |top_by_score(alpha) intersect top_by_pH(alpha)| /
                       |top_by_pH(alpha)|

  Tail curve L1 error:
      mean over tau grid of max(0, tail_bound(tau)-tail_exact(tau)).

Tau grid:
  - include exact unique p_H values for toy runs if not too many;
  - otherwise use logarithmic grid plus 0:
      0, 1e-6, 3e-6, 1e-5, ..., 1.

7.10 src/rare_event.rs

Responsibilities:
  - conditional sampling/enumeration of errors with large near-codeword overlap;
  - compute p_{H,u}^N and contribution A_H^N(u)*p_{H,u}^N.

For exact small runs:
  - enumerate all e in E_t;
  - for each u, keep e if U_N(e)>=u;
  - compute conditional failure rate exactly.

For sampled larger runs:
  - sample e uniformly from E_t until enough conditional samples are collected;
  - record total draws and accepted draws;
  - report one-sided confidence intervals if requested.

Output rare_event.jsonl:

  {
    "key_id": 123,
    "u": 3,
    "tail_mass_A_union": 0.0041,
    "conditional_total": 715,
    "conditional_failures": 88,
    "p_conditional": 0.1231,
    "contribution_proxy": 0.000504,
    "exact_conditional": true
  }

9. CLI SPECIFICATION
================================================================================

Binary name: dfrcert

Commands:

  dfrcert run --config <path> --out <dir>
      Full pipeline: generate/enumerate keys, compute profiles, enumerate/simulate
      errors, compute p_H, build bins, compute bounds, metrics, and outputs.

      Generate keys and compute profiles only.

      Run near-codeword conditional diagnostics.

      be used for final claims unless the selected final config is rerun from

The implementation should be able to complete the exact r=11,d=3,t=3 run inside

Performance design requirements:
  - precompute column masks for each key;
  - use u128 syndrome masks and fixed-size Mask256 error masks;
  - avoid storing per-error logs by default;
  - aggregate counts online;
  - flush CSV/JSON periodically;
  - parallelize over keys using rayon;
  - ensure deterministic output ordering despite parallel execution.

Parallelism:
  - use rayon for per-key parallelism;
  - collect per-key outputs in memory or temporary files;
  - merge by increasing key_id before writing final outputs.

  - with the same config and seed, outputs must be byte-stable except for
    timestamps in manifest.json;
  - if byte-stability is difficult, data CSVs must be stable and manifest may vary.

================================================================================
16. NUMERICAL PRECISION
================================================================================

Use integer counts wherever possible.

For probabilities:
  - compute p_H as failures as u128 divided by total_errors as f64;
  - store failures and total_errors so exact rational values can be recovered;
  - use f64 for metrics and plots;
  - coverage comparisons use epsilon = 1e-15.

For row sums and upper-process propagation:
  - use f64;
  - cap final p_phi_FS_plus at 1.0;
  - do not cap intermediate alpha values, because non-normalized upper kernels may
    exceed probability mass; record alpha_total_final.

================================================================================
17. VALIDATION INVARIANTS
================================================================================

The implementation must check these invariants at runtime and fail loudly if they
are violated.

Key/profile invariants:
  - h0 and h1 have size d;
  - supports contain unique positions in [0,r);
  - column masks have popcount d;
  - D_aa(0)=d;
  - D_ab(Delta) in [0,d].

Decoder invariants:
  - syndrome(E_i) equals logged syndrome at every iteration;
  - E_i = original_error XOR estimate_i;
  - missed_count + true_flipped_count = residual_weight;
  - false_count + clean_unflipped_count = 2r - residual_weight;
  - E_{i+1} = missed_mask union false_mask;
  - success iff final residual mask is zero.

Enumeration invariants:
  - number of enumerated errors equals binom(2r,t) in exact mode;
  - sum of outcome counts equals total_errors for each key;
  - state denominators match number of trajectories reaching iteration i.

Certification invariants:
  - direct bin p_phi_max >= p_H for every key in bin;
  - Q_i^+(phi,x;m,l) >= q_{i,H}(x;m,l) for every key H in bin;
  - terminal states are absorbing;
  - finite-state p_phi_FS_plus in [0,1] after final cap;
  - reported finite-state coverage equals 1.0 on exact certified domains.
